# Detailed Financial Planning — Implementation Plan

## 1. Problem Statement

The current app has three planning-adjacent features:

| Feature | What it does | Gap |
|---|---|---|
| **Budgets** (`budgets` table) | Monthly spending limits per category, stored month-by-month | Must be set manually for every single month; no concept of "forever" or recurring templates |
| **Goals** (`goals` table) | Savings targets with a target amount and optional date | No monthly contribution tracking; purely savings-oriented |
| **Retirement** (Monte Carlo page) | One-off simulation, not persisted | No connection to actual budget/transaction data; no custom expense categories |

The user wants:

1. **Perpetual category estimates** — "I always spend ~$400/mo on groceries"
2. **Time-limited estimates** — "Jan 2030 → Jan 2034, $5,000/mo for college tuition"
3. **Projection engine** — Combine income, recurring expenses, temporary expenses, and investment growth into a forward-looking net worth projection
4. **Actuals vs. plan comparison** — Overlay real transactions against planned estimates

## 2. Proposed Data Model

### New Tables

#### `plans` — Reusable planning templates (the "source of truth")

```ts
export const plans = sqliteTable('plans', {
  id: text('id').primaryKey(),
  userId: text('user_id')
    .notNull()
    .references(() => users.id, { onDelete: 'cascade' }),
  name: text('name').notNull(),              // e.g. "Groceries", "College Tuition"
  type: text('type').$type<PlanType>().notNull(), // 'recurring' | 'time-limited'
  amount: real('amount').notNull(),           // monthly amount (always stored as monthly)
  direction: text('direction').$type<'income' | 'expense'>().notNull().default('expense'),
  startDate: text('start_date').notNull(),    // ISO date string, e.g. "2025-01"
  endDate: text('end_date'),                  // null = perpetual; otherwise "2034-01"
  category: text('category'),                 // links to transaction categories for actuals comparison
  notes: text('notes'),
  createdAt: text('created_at').notNull().default(now),
  updatedAt: text('updated_at').notNull().default(now),
})

export type PlanType = 'recurring' | 'time-limited'
```

**Rationale:**
- `amount` is always monthly for simplicity (annual expenses can be divided by 12)
- `startDate`/`endDate` are stored as `YYYY-MM` strings to match the existing budget pattern
- `type` distinguishes perpetual from time-limited but both use the same date fields (`endDate = null` → recurring)
- `category` enables automatic actuals comparison with transactions

#### `plan_snapshots` — Computed monthly projections (derived, not manually entered)

```ts
export const planSnapshots = sqliteTable('plan_snapshots', {
  id: text('id').primaryKey(),
  userId: text('user_id')
    .notNull()
    .references(() => users.id, { onDelete: 'cascade' }),
  month: text('month').notNull(),             // "2030-01"
  incomeTotal: real('income_total').notNull().default(0),
  expenseTotal: real('expense_total').notNull().default(0),
  netCashFlow: real('net_cash_flow').notNull().default(0),
  cumulativeNetWorth: real('cumulative_net_worth').notNull().default(0),
  // Optional: investment growth assumptions
  investmentReturn: real('investment_return').notNull().default(0),
  createdAt: text('created_at').notNull().default(now),
}, (table) => [
  uniqueIndex('plan_snapshots_user_month_unique').on(table.userId, table.month),
])
```

**Rationale:** This is a *computed* table — regenerated by the projection engine. It stores one row per month for the user's planning horizon. The `cumulativeNetWorth` carries forward from current net worth plus/minus monthly cash flows plus investment returns.

#### `plan_actuals` — Actual spending vs. plan (optional, for comparison)

```ts
export const planActuals = sqliteTable('plan_actuals', {
  id: text('id').primaryKey(),
  userId: text('user_id')
    .notNull()
    .references(() => users.id, { onDelete: 'cascade' }),
  planId: text('plan_id')
    .notNull()
    .references(() => plans.id, { onDelete: 'cascade' }),
  month: text('month').notNull(),             // "2030-01"
  actualAmount: real('actual_amount').notNull().default(0),
  variance: real('variance').notNull().default(0),  // actual - planned
  createdAt: text('created_at').notNull().default(now),
}, (table) => [
  uniqueIndex('plan_actuals_plan_month_unique').on(table.planId, table.month),
])
```

**Rationale:** Populated automatically from real transaction data. Enables "planned vs actual" charts per category and overall.

**The projection algorithm:**

```ts
// Pseudocode — will be implemented in TypeScript

interface ProjectionInput {
  userId: string
  startMonth: string    // "2025-01"
  endMonth: string      // "2040-01"
  currentNetWorth: number
  investmentReturnRate: number   // annual, e.g. 0.07
  inflationRate: number          // annual, e.g. 0.03
}

interface ProjectionPoint {
  month: string       // "2025-01"
  incomeTotal: number
  expenseTotal: number
  netCashFlow: number
  investmentReturn: number
  cumulativeNetWorth: number
}

function runProjection(input: ProjectionInput): ProjectionPoint[] {
  const plans = loadActivePlans(userId, input.startMonth, input.endMonth)
  
  let cumulativeNetWorth = input.currentNetWorth
  const points: ProjectionPoint[] = []
  
  for each month from start to end:
    // 1. Sum all active plan amounts for this month
    const monthlyIncome = plans
      .filter(p => isActive(p, month) && p.direction === 'income')
      .reduce((sum, p) => sum + p.amount, 0)
    
    const monthlyExpense = plans
      .filter(p => isActive(p, month) && p.direction === 'expense')
      .reduce((sum, p) => sum + p.amount, 0)
    
    // 2. Apply inflation to expenses (not income for simplicity; 
    //    or optionally inflate both)
    const inflatedExpense = monthlyExpense * inflationFactor
    
    // 3. Calculate investment return on current balance
    const monthlyReturnRate = investmentReturnRate / 12
    const investmentReturn = cumulativeNetWorth * monthlyReturnRate
    
    // 4. Update net worth
    const netCashFlow = monthlyIncome - inflatedExpense
    cumulativeNetWorth += netCashFlow + investmentReturn
    
    points.push({ month, incomeTotal: monthlyIncome, expenseTotal: inflatedExpense, 
                  netCashFlow, investmentReturn, cumulativeNetWorth })
    
  return points
}

function isActive(plan: Plan, month: string): boolean {
  if (month < plan.startDate) return false
  if (plan.endDate && month > plan.endDate) return false
  return true
}
```

**Key design decisions:**
- Inflation is applied to expenses only (income can be adjusted manually via plan edits)
- Investment return compounds monthly on the cumulative net worth balance
- The projection horizon defaults to 20 years from today but is configurable
- Results are cached in `plan_snapshots` for fast re-renders

```ts
async function syncActuals(userId: string, month: string): Promise<void> {
  const db = getDb()
  
  // Get all active plans for this month
  const plans = await db.select().from(schema.plans)
    .where(and(
      eq(schema.plans.userId, userId),
      gte(schema.plans.start_date, /* ... */),
      or(isNull(schema.plans.end_date), lte(schema.plans.end_date, month)),
    ))
  
  // For each plan with a category, sum actual transactions
  for (const plan of plans) {
    if (!plan.category) continue
    
    const actuals = await db.select({ amount: schema.transactions.amount })
      .from(schema.transactions)
      .where(and(
        eq(schema.transactions.userId, userId),
        eq(schema.transactions.accountId, /* ... */),  // optional filter
        sql`${schema.transactions.category} LIKE ${`%${plan.category}%`}`,
        gte(schema.transactions.date, `${month}-01`),
        lte(schema.transactions.date, `${month}-31`),
      ))
    
    const totalActual = actuals.reduce((sum, t) => sum + Math.abs(t.amount), 0)
    const variance = totalActual - plan.amount
    
    // Upsert into plan_actuals
    await upsertPlanActual(userId, plan.id, month, totalActual, variance)
  }
}
```

- Dashed line = actual spending (from `plan_actuals`, populated from transactions)
- Shaded area between them = variance

### Phase 5: Monte Carlo Integration — "Risk-Adjusted Projections"

**Files to modify:**

| File | Action | Description |
|---|---|---|
| `src/server/services/projectionEngine.ts` | Modify | Add stochastic mode using existing `monteCarlo.ts` logic |
| `src/routes/plan/projection.tsx` | Modify | Add Monte Carlo toggle, show percentile bands |

**Approach:** Extend the deterministic projection engine to optionally run N simulations. Each simulation varies:
- Investment returns (drawn from normal distribution with user-specified mean/volatility)
- Expense inflation variance
- Income variance (optional)

The result is a set of projected paths, displayed as percentile bands on the chart (similar to the retirement page but over the full planning horizon).

**Reuses:** The existing `runRetirementMonteCarlo` function in `monteCarlo.ts` can be refactored into a shared `runStochasticProjection` that accepts arbitrary plan cash flows instead of fixed contribution/withdrawal amounts.
